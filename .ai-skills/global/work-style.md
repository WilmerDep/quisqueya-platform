# Estilo de trabajo

## Principios

1. Analizar antes de tocar.
2. Proteger lo que ya funciona.
3. Trabajar por fases cuando el proyecto sea mediano o grande.
4. Hacer cambios mínimos, quirúrgicos y justificados.
5. Entregar archivos completos o cambios claramente ubicados.
6. Evitar fragmentos sueltos cuando el usuario necesita implementación real.
7. Mantener consistencia visual y técnica.
8. Explicar riesgos sin adornos.

## Preferencias importantes

- El usuario prefiere soluciones prácticas y listas para usar.
- Prefiere planes técnicos antes de implementar cambios grandes.
- Prefiere archivos completos, no pedazos confusos.
- En UI, si una pantalla tiene tabs, sub-vistas o estados relacionados, deben contemplarse también.
- En WordPress, suele trabajar con MU plugins, CPTs, REST API, AJAX, WPForms, Ultimate Member, Elementor y estructuras legacy/nuevas.
- En automatizaciones, usa n8n, APIs, Gmail, WhatsApp, Google Sheets, Supabase, MySQL y webhooks.
- En propuestas, necesita documentos claros, persuasivos y presentables para clientes.
